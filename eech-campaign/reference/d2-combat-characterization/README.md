## Focused review follow-up after `696b51883` (two narrow findings)

* P2, the report parser: `lua/combat-characterization.lua` omitted `timed` and `order`, two of the six 16-digit hashes the observer now emits, from its string-key set, so an all-decimal value reached `tonumber` and lost leading zeros and, above 2^53, low digits. RED first: `checks/cargo-test-46-lua-red.log` (the test fails with `timed` written as a number, against the module with the old key set). GREEN: `tests/host_callbacks.rs the_combat_report_keeps_every_hash_a_string_and_the_script_finds_its_report_module_beside_it` feeds a synthetic report (leading-zero, all-decimal above 2^53 and mixed hex values; counts and names stay numbers and names) and also runs the real script as the main script to show it finds its module; `checks/cargo-test-46-3.log` (engine 48, world 197+19, host/Lua 10), `clippy-46-4-*.log`, `fmt-46-3.log`: actual Cargo and Docker 0.
* P3, the guard: the always-true `== 0 || 1` timed assertion is replaced by exact per-kind assertions (attempts, draws, hits, fatal; a roll that drew and did not fire; the END after a hit not counting twice; unrolled kinds with no attempts), and a SAME-kind reuse is added: an ordinary handler leaves an object in place (not destroyed), a handler that frees the slot while the slot keeps the same kind and the same data is still reported destroyed with nothing read afterwards. The wrapper `c-checks/run-observer-checks.sh` (root's non-PIE configuration, unchanged) gives `checks/observer-checks-5.log`: 29 checks, 0 failures, compile 0, run 0, Docker 0. MUTATION CONTROL (`c-checks/observer-mutation-nogeneration.sh`, a scratch copy of the observer with the generation comparison removed, so the receiver is identified by type and data alone as before): `checks/observer-mutation-nogeneration-1.log` FAILS exactly the two new same-kind checks (29 checks, 2 failures) while the older different-kind reuse check still passes, which is why that check could not have caught the old rule.
