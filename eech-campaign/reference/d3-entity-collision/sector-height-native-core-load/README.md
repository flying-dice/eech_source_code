# Core load of the real generated saved script: bounded diagnosis (ENV-SECTOR-HEIGHT-NATIVE-CORE-LOAD-LIST-1)

First real Core save (feature profile of the exact 17f) passed native 0. A fresh Core boot of that actual generated saved script stopped native 1 after 1748 sector restores with `Invalid list type (ENTITY_TYPE_SECTOR, index 0, LIST_TYPE_FORCE)` at `en_list.c:356`. **The fatal is a symptom**: the saved sector section decodes exactly to the save report's words (`decode-result.json`), but the load stated zero for every sector, so the unpack buffer was zero where the file holds data; an all-zero stream reads the session's force root as entity index 0, the sector 0 entity, and the force loop asks it for a force-list successor. The legacy loader (`parsgen.c`, `FILE_TAG_SAVED_CAMPAIGN`) sizes the data with a text-mode helper, reads it with a one-element `fread` and ignores the unpack's overflow flag; the data holds Ctrl-Z bytes from offset 167. See `diagnosis.json` for facts, locations, ranked candidates, the intended bounded fix and what it does not establish.

`decode-saved-sector-section-20261107.py` re-implements only the sector section over the retained private artifacts and writes aggregates; the artifacts, words and coordinates stay outside Git. Not a native result, a fix claim, or an acceptance of M6.
