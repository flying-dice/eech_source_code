## The fixture

`engine:env_case(group, index)` returns `key=value` text lines; one call is one case (32 KiB buffer; a report that does not fit is refused, never cut). Groups: **0 census** (case counts, enum values, constants, the configured `EECH.INI` radii and speeds, the map extents, and the
`env-unsupported` items) and **1 retail snapshot** (read-only; `tag=retail`) are the only calls that look at the unmodified session; **2–8 are controlled witnesses** (`kind=witness`): the case sets only the session fields it names, calls the original routine, prints the words,
restores, and ends with `env-witness-end restored=1|0 fp_before fp_after`. A witness that did not restore is a fixture defect and fails the run. What is restored: the whole session record, the map season, the shared seed word `random_number_seed` (the libc generator is never touched)
and `system_delta_time`. A path through the engine's fatal handler cannot restore anything; every case is domain-guarded so no original `ASSERT` fires (a gust outside [0,1) is **refused and printed, never called**).
Floats are IEEE-754 words (`_w`, `%08x`), so a signed zero or a neighbouring float is visible; fingerprints are FNV-1a 64 of the rendered state text.

## Driver, commands and protocol (for the root; none of this has been run)

Build (Git Bash, Docker, Linux containers; from a clean checkout of the commit to characterise): `tools/build-windows-env-fixture.sh target/env-fixture/<dir>`. For a feature-enabled check of the Rust: `cargo test -p eech-world`, and clippy/fmt as for the other fixtures, with and without `--features eech-dc/env-fixture`.

```
eech-world lua/env-characterization.lua root=<verified retail root> out=<env-lebanon-probe.jsonl> scenario=lebanon_retail seed=1 seconds=120 frame_ms=100 probes=512 probe_at=0 snapshot_frames=20 snapshot_every=60
eech-world lua/env-characterization.lua root=<same root>                out=<env-lebanon-control.jsonl> scenario=lebanon_retail seed=1 seconds=120 frame_ms=100 probes=0   probe_at=0 snapshot_frames=20 snapshot_every=60
```
and the same pair with `scenario=georgia_retail`. A DLL built **without** the feature is refused: a `refusal` row, the message `the engine has no env_case method`, a non-zero exit, no frame run. Every argument is validated before the output file is created or anything is prepared or booted.

**Control protocol (probe noninterference).** The pair above differs only in `probes`. Expected, to be checked by the root: every `snapshot` row of the two runs (initial, frames 1–20, periodic, final), the `campaign_end` row and the clock are byte-identical apart from the `boot` row's `probes`/`mode`;
inside the probe run, `probe_noninterference` is true (retail and campaign fingerprints equal before and after the whole witness set) and every witness ends `restored=1`. A single difference is a finding about the fixture, not a result about the original. Repeat each run once to
show whether two runs of the same command are identical (the seed, the simulated clock and the schedule are fixed; the engine's other nondeterminism is not assumed away).

**Output schema (JSON Lines, sorted keys, one object per line, written with every write/flush/close checked).** `boot` (arguments, `mode` control|probe); one object per report line with `event` = the line's first word, `scope` (`census`, `snapshot:initial`, `snapshot:frame:N`,
`snapshot:periodic:T`, `snapshot:before_probes`, `snapshot:after_probes`, `snapshot:final`, `probe:g<group>:<index>`), `at` (simulated seconds) and the line's fields; keys ending `_w` and `fp*` are **strings** (all-digit words stay strings), other plain decimal values are numbers;
`campaign` rows (object count, alive, a polynomial fingerprint of `engine:objects()` at the start, around the probes and at the end); `probe_noninterference`; `coverage` (per group); `run` (frames, probes requested/run, cases available, `complete`, unsupported items). `refusal`/`failure` precede a non-zero exit.

## Prepared corrections after the first independent review (validator, scheduler, test wiring; UNBUILT, UNRUN, UNREVIEWED)

The review of head `8e676a9a` found three P2 groups, all in the driver and its tests; no C, numerical, FFI or restoration blocker. They are corrected as follows. None changes a physical answer, a baseline, a tolerance or an output row of a well-formed report.

1. **The emitted protocol is validated, not just the end marker.** `lua/env-characterization.lua` parses each report strictly (truncated, empty, non-ASCII, malformed or duplicate fields, size) and writes it out as it came, then accepts it only with the protocol shape for the group asked: the rows in order and their keys in order; every value of its kind (8-digit lowercase hex word, 16-digit fingerprint, integer, flag, token); the case identity (`i`, the end marker's group and index, the `before_N`/`after_N` tags); the declared supported or refused form of each family (wind, gust, init and update-weather have a refused form; the two gust refusals must carry a word outside [0,1) and a called gust a word inside it); the end marker `restored=1` with `fp_before` equal to `fp_after`; and a census with the header enum values, six unsupported items in order and every count within the C table capacities (1 or more, total at most 1024). A forged zero census, a marker-only or wrong-family report, a missing, extra, duplicate or mistyped field, a wrong identity or a changed fingerprint is a `failure` row and a non-zero exit. It checks the SHAPE only: no physical answer is recomputed or compared with an expected number. A new `validation` row (before `run`) reports reports accepted, witnesses and refused witnesses.
2. **The periodic snapshot schedule is bounded.** The `while next <= clock do next += period` catch-up (about 10^10 steps for `snapshot_every=.00000000001` after one 100 ms frame, for no extra observation) is replaced by `advance_periodic`, which reaches the next due time in constant work (whole periods in one step), requires it to lie after the clock and be finite, and refuses a period below the clock's resolution. One snapshot per frame at most, as before; the default 60 s schedule and the ordinary schedules give the same times as stepping one period at a time.
3. **The guard tests are portable.** The tests embed the exact driver with `include_str!` and write it, with a generated stand-in, to a per-run temporary directory (removed afterwards); no `CARGO_MANIFEST_DIR` or source tree is used at run time. The host binary is `CARGO_BIN_EXE_eech-world` unless **`EECH_WORLD_TEST_HOST`** names another: it must be an absolute path to an existing file, and a supplied value that is empty, relative, missing or a directory is REFUSED (the test panics naming it), never replaced by the Cargo path. If no override is given and the Cargo path does not exist (a cross-built test executable) the tests refuse with the same instruction rather than skip. Each run has a 90 s deadline and is killed and failed if it does not finish.

4. **Guard context is judged (second review, residual P2; prepared, UNRUN).** The first validator accepted a supported or refused alternative without checking the condition the emitter prints for it, so an impossible refusal could hide the rows it replaces. `validate_report` now judges the guards `csrc/eech_env_fixture.c` actually uses, from the report's own printed context and the census: an initialiser refusal needs `comms_model` different from the census `comms_server`, and a run needs it equal in its state rows; a weather-update refusal needs `in_cockpit` non-zero, `camera` 0 or a non-server model, and a run needs `in_cockpit=0`, `camera=1` and the server in every state row; a retail snapshot's or initialiser's query (both templates admit the stated absence of wind, since the initialiser leaves the gust phase untouched) has wind values exactly when the `gusting_value_w` of the SAME report is inside [0,1), and `wind=unavailable_gust_outside_0_1` exactly when it is not (controlled update-state records are not query contexts and may show a gust phase of 1.0 before it wraps); and the wind row's `null_same` must equal the equality of its own two printed words `speed_w` and `null_speed_w` (flag 1 with equal words and flag 0 with unequal words are both coherent). No wind speed, weather answer or any other physical value is recomputed or compared with an expected number. The positive stand-in is now coherent (in-domain gust in every state row, equal speed words with flag 1).

Selected tests (`crates/eech-world/tests/host_callbacks.rs`): `the_environment_host_override_is_strict_and_never_falls_back`, `the_environment_driver_refuses_a_malformed_argument_before_anything_is_prepared_booted_or_run` (20 arguments), `the_environment_driver_refuses_a_module_without_the_fixture_and_runs_no_frame`, `the_environment_driver_control_asks_for_no_witness_and_the_probe_run_keeps_words_as_strings_and_reports_its_coverage`, `the_environment_driver_accepts_every_family_in_its_declared_form_including_the_genuine_refusals_and_counts_them` (well-formed per-family stand-in; 14 cases, 2 refused), `the_environment_driver_refuses_every_report_that_is_not_the_fixtures_protocol` (34 damaged reports across the families, one damaged report per run, including the guard-context and `null_same` negatives), `the_environment_driver_bounds_its_periodic_schedule_whatever_the_period_and_the_clock_jump` (a 1e-11 s period with 50 s clock jumps through the real driver, and the ordinary 0.5 s / 0.25 s / off schedules). The stand-in is canned: these checks say nothing about the original's weather, wind or clock. `every_shipped_lua_script_parses_under_the_hosts_lua` also parses the driver.

How the regressions are protected: each group of the first correction has a mutation case that the previous driver ACCEPTED (it counted any report ending `restored=1`, and the old stand-in returned `env-wind` for every group), now refused; the guard-context negatives (impossible initialiser/update refusals and runs, false and missing wind unavailability, both contradictory `null_same` flags) were accepted by the driver before item 4 and are refused after it, while the coherent alternative forms (unequal words with flag 0, a snapshot with the gust outside [0,1), each other refusal guard, a state record with gust phase 1.0) are accepted by `the_environment_driver_accepts_the_coherent_alternative_forms_the_emitter_can_print`; the periodic test would hit the 90 s deadline against the old loop; the override test and the embedded driver remove the baked-in paths. Whether the new tests fail on the old driver is argued from its source here, not demonstrated by a run. **Linux and the actual Windows guard execution are the root's to run** — for Windows, export the cross-built test executable and run it with `EECH_WORLD_TEST_HOST=<verified eech-world.exe>`; nothing is claimed passed. ## Expected native limitations and unknowns (not results)

* No part of this compiles or runs yet: header names and macros (`knots_to_metres_per_second`, `MIN_MAP_X`, `in_cockpit`, `system_delta_time`, `nextafterf`) are used as `session.c`/`ss_updt.c` use them and need the root's real-header compile (the other fixtures' `syntax-*.log` method).
* The camera entity's headless position is unknown; the local-model `weather_mode` of an unmodified frame, and of the group 8 cases, depend on it (printed as `camera_*_w`). The retail weather model (local, fixed dry), season and map extents are read, not assumed.
* The ring-edge inputs are derived in the engine's round-toward-zero mode and printed as words; a different rounding mode on a later path gives different input words, which the comparison would show rather than hide.
* The first frame's delta (source: 0.1 s) and the per-frame increments are unconfirmed until the snapshots are read.
* Coverage of one scenario/seed is not coverage of other seasons or of a fixed-weather campaign file; the desert/summer/winter cases are synthetic season values, not retail maps.
