**When the M4 pack differs.** A failing pack produces a proposal, never a new baseline. Runners can't re-record (`-Update` is refused), and tolerances are never widened.
1. `baseline-governance.py propose` turns the failing report into a change record, with every difference marked UNCLASSIFIED.
2. Each difference is classified with evidence as exactly one of: regression (rejected; the candidate stays failing), approved defect correction, intentional semantic change, or expected input/world variation (which starts a separate baseline lineage).
3. The PR carries the report from before the change, the record, and the old and proposed baseline identities.
4. Only the lead's APPROVED review of the commit holding that exact record counts.
5. A follow-up commit adds the approval reference and runs `adopt`. The tool checks the review on GitHub, keeps the superseded version, and the new commits need fresh approval.
